# Обход сайта miacso.ru: что и как собрано

## Результат

Локальная копия действующего сайта **https://miacso.ru** (CMS Joomla,
шаблон `new_shablon_osnov_5_16_norm` от Artisteer).

| Параметр | Значение |
|---|---|
| HTML-страниц | **910** (все HTTP 200) |
| Объём HTML | 63 МБ |
| Текст страниц извлечён | 910 из 910 |
| Внешних ссылок зафиксировано | 711 |
| URL отфильтровано политикой | 11 726 |
| Неуспешных URL | 44 (битые ссылки и недоступные поддомены самого сайта) |

### Скачивание вложений приостановлено

Файлы-вложения (≈1186 штук: PDF, DOCX, XLS/XLSX, DOC, ODT, PPTX и изображения)
**не скачивались** — по решению заказчика на этом этапе они не нужны.
Полный список со ссылками доступен в `mirror/inventory.json` (поле
`attachments_not_mirrored`) и в `mirror/INVENTORY.md`.

Чтобы докачать их позже, достаточно запустить `python tools/crawl.py` —
обход страниц будет пропущен (они уже в манифесте), и начнётся загрузка
вложений. Затем `python tools/doctext.py` извлечёт из них текст.

| Что | Где |

## Правила обхода

1. **Только домен `miacso.ru` и его поддомены.** Ссылки на другие домены
   (minzdrav.gov.ru, egov66.ru, pos.gosuslugi.ru и др.) не скачиваются,
   а фиксируются в `external_links.json`. Это ссылки «наружу», их содержание
   к сайту не относится.
2. **Ограничение частоты** — 0.6 с между запросами, до 3 попыток на URL,
   дисковый кэш ответов (`_cache/`), чтобы повторный запуск не бил по серверу.
3. **Политика URL-пространства.** Компонент календаря событий Joomla
   порождает бесконечное множество адресов: для каждой даты каждого года
   существует вид «день», «неделя» и карточка события, и каждая из них
   ссылается на следующие. Наивный обход по ссылкам не завершается.
   Сохраняется только вид «месяц» (`month.calendar`), который содержит
   собственно расписание; виды `day.listevents`, `week.listevents` и
   `icalrepeat.detail` пропускаются. Список пропущенного —
   `mirror/urls_skipped.json`.
4. **Технические служебные пути** (`/administrator`, `/components/com_*`,
   `/cli/`, `/cache/`, `/logs/`) не обходятся.

## Исправленные проблемы, найденные в процессе

| Проблема | Проявление | Решение |
|---|---|---|
| BOM в начале страниц | `<title>` не читался | снятие BOM перед разбором |
| Совпадение пути файла и каталога | `/home` и `/home/kontakty` конфликтовали | URL без расширения → `<path>/index.html` |
| Превышение MAX_PATH Windows | ошибка `WinError 206` на длинных слагах | усечение сегментов + хеш URL |
| Ссылки на другие домены | crawler уходил на minzdrav.midural.ru | проверка домена на этапе обнаружения |
| Редиректы | разные URL писались в один файл | запись по итоговому URL + учёт занятости пути |
| Бесконечное пространство URL календаря | очередь росла до тысяч | политика `url_allowed` |

## Известные особенности исходного сайта

* Корень `/` отдаёт **404** — фактическая главная страница это `/home`.
* `robots.txt` и `sitemap.xml` отсутствуют.
* Один и тот же раздел доступен по нескольким адресам (`/home/kontakty`,
  `/index.php/home/kontakty`, `/index.php?option=...`).
* Часть ссылок на вложения ведёт на внешние ресурсы (например, `egov66.ru`)
  и не входит в этот миррор.
